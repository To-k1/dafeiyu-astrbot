# 小队的多会话与双向长期记忆

本次接线继续使用已有名册、稳定 agent_id、人格版本、异步队列和原始记录。没有迁移或覆盖既有小弟，没有安装另一套 DS-Bot 宿主，没有改写人格正文。

## 日常使用

可以自然地让肥鱼“给某位小弟另开一段聊某主题”“切回上次那段聊天”“查你们以前的约定”“更正这条记忆”。她使用原工具自行操作，不要求主人记命令格式。

`df_dsh_chat` 的 `session_new/list/select/archive` 管理同一小弟的不同日常聊天；默认续接当前选择。消息在入队时固定目的会话，后续切换不会改变已排队消息。归档保留原生历史；选择归档会话即可恢复。新会话第一次实际发送才创建原生 DSH Session，不会为了新建元数据花模型费用。

`df_dsh_memory` 的 `sources/source` 检索原始经历；`search/get` 查相关长期记忆；`save/update/forget` 管理有来源的记忆。留空 agent_id 是肥鱼本人，指定已有小弟则是其个人记忆。不确定写入使用 reconcile，对账不能确定时保留待核对，不盲目重新保存。

## 复用与数据归属

DS-Bot 的现成记忆入口依赖其自己的 runtime、Bot 名册与 Session 映射。此次未引入第二套名册；复用已经安装的 LivingMemory 原生 MemoryEngine、索引与嵌入提供者。相对于重新实现记忆算法，这是引擎复用及薄接线。

肥鱼的长期记忆仍在原 LivingMemory 数据库，沿用现有访问范围和人格。小弟索引位于 B站活动插件数据目录的 `dsh_team_memory/livingmemory.db` 与 `livingmemory.index`，按稳定 agent_id 及原生 adapter 边界隔离。它是小弟的记忆存储，不是第二套肥鱼记忆库。

必须单独存放小弟索引的原因：LivingMemory 允许某些配置下跨 adapter 全局检索，仅在同库写入不同 metadata 或 scope 并不能保证普通检索不会混入小弟私人记忆。独立数据目录使主人正常召回根本不搜索小弟的私库，不需修改已有全局过滤设置。小弟主动检索也不会进入主人整套记忆。

活动数据库只增加会话元数据、记忆来源与写入回执，不再存一份完整长期记忆正文。原生备份已纳入小弟记忆数据库；运行端完整快照仍应保留活动库，才能同时恢复名册、原始记录和记忆引用。运行中备份使用 SQLite 一致性快照；索引文件只在停止写入时一并打包，缺失时须按原生引擎恢复索引。

## 事实与评价

来源引用是 `chat:...`、`meeting:...`、`task:...`、`public:...`、`agent:ID:版本`。访问范围不代表发言人。每条记忆保留所属者、参与者、原始记录引用、归纳者及评价作者；未确认的原始说话人留空，不能由主人 event 自动推成主人。

系统只自动记录真实已完成的交流/合作、组织会议和实际名册变化等生活事实，不替肥鱼生成喜欢或讨厌。重要内容与她自己的评价可由她在回报或普通交流时主动保存。小弟通过技术协议选择值得保留的事实、约定、经验及其本人评价；这不修改小弟人格，也不规定聊天台词。

各会话首次交谈及后续交谈可按当前话题检索自己的相关记忆和来源概览，不载入全部历史。小弟可主动请求进一步搜索或完整来源；聊天、任务和会议都在对应原生会话内接收查询结果。续轮请求先持久化再发送，重启只接收原请求；Go 额度恢复只续接查询，不重新执行原任务。

原文件任务的数据库 result 原本最多保存 1200 字，来源接口会明确说明并提供完整报告路径，不把该摘要说成完整报告。

2026-11-18 QQ 联调修复：小弟聊天的记忆提案在有真实 Go 回执的原生回合完成后即可保存并回读，无须等待整段聊天结束。来源使用 `chat:聊天ID:turn:原生请求ID`，查询先取得已保存 ID，再读取记忆；不会把“待保存的提案”误当成存储故障。每轮要求隐藏协议明确选择记忆或返回空列表；缺失时只在同会话补全一次，保留原答复，不重发原问题或凭口头“记下了”自动提取。补全失败会明确记录未确认。写入未回读确认时不报告保存成功。

原生聊天已完成而 Go 回执稍晚到达时，系统保留回复并复查原回合与账单。确认后恢复原答复。同一原生会话等待核对，已确认终态的回合不占用其他会话。`df_dsh_memory` 的 `rebind_source` 可按记忆 ID 更正出处。更正保留条目 ID、正文和原写入来源。后台公开网页任务说明上限 4000 字，单次搜索词上限 500 字，失败时可查询最后执行阶段。`/go额度` 使用 FishHome 控制台已保存的 Go Key，通过与 `dsh-opencode-go` 相同的官方只读接口，查询正式任务账户的订阅窗口。

## 验收与回滚

自动测试使用临时数据及模拟模型；真实 LivingMemory/FAISS 测试仅替换嵌入为确定性向量，验证隔离、增删改查、对账与关闭重开，不调用真实付费模型。最终结果和运行端部署状态见同日检查点。

主人醒后集中验收：

1. A：同一小弟建两段不同主题的聊天；分别续接，归档恢复后仍准确；重启服务后再次续接。
2. B：在 A 会话形成一个新约定，让它自行判断并记住；另开 B 会话询问约定及来源，不手动粘贴原对话。后台核对原生记忆回执。
3. C：肥鱼与小弟完成一件具体合作后，主人 `/new`，询问该经历；核对肥鱼原 LivingMemory 的真实条目、来源和评价作者。不能把小弟“我喜欢X”归纳为主人喜欢X。
4. D：两位小弟完成一场带结论的组会；新开其中一位日常聊天查结论和来源；肥鱼也应能找到曾组织会议的事实。重启后复核。

回滚前暂停新增交谈、等待在途请求保存并停止 AstrBot，恢复部署前代码。保留所有新增会话元数据、索引及来源回执，禁止删除或覆盖正式历史。旧代码只忽略新字段，不能继续新版本的多会话切换/记忆查询；需要先核对尚在途的记忆续轮。
