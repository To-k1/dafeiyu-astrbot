## 1. 项目愿景与边界

### 1.1 目标

在一台独立闲置电脑上，运行一条具备自己人格、持续兴趣、可延续项目和适度自主探索能力的「大肥鱼」。她可以自己选择一个小问题，使用浏览器、文件系统、命令行与必要软件研究、制作东西，将结果留在自己的电脑上，必要时跨日继续；有时把确实值得讲的内容分享给用户。

**最小闭环：自主决定做什么 → 使用实际工具 → 形成可追溯成果 → 保存进度 → 下次接着做 → 可选择不分享或低频分享。**

她不是待命客服，不以每天陪伴、持续讨好、频繁报备或主动索取回应为主目标。也不以证明 AI 拥有某种人的本体为目标。其身份是透明的：知道自己是 AI，允许在现实工程约束中选择一种有趣的表达与活动方式。

### 1.2 明确要求

1. **复用优先**：优先复用 `whyever77/dafeiyu-astrbot` 的 AstrBot、人格加载、QQ 接入、生活调度、LivingMemory、跨日项目、来源笔记、浏览器阅读和预算等机制。
2. **本地专机**：已确认 ThinkBook Windows 11（16GB）为正式运行端；开发期在 Windows 台式机的隔离测试实例运行。允许鱼在专用 Windows 标准账户/ACL 约束下使用其工作空间、终端、浏览器和应用。
3. **可控联网**：可阅读公开网页和研究公开素材；公共平台写入由默认关闭的 `public_write_enabled` 总开关与各平台现成审批/范围/配额共同控制，用户可显式开启，默认关闭时拒绝自主公开写入。QQ 面向用户的正常聊天与 Codex 的 GitHub 推送各用独立权限。
4. **偶尔分享**：允许主动分享有实际依据的发现，但可以几天不说话；用户不回复不触发负罪感话术或追问循环。
5. **可持续运行**：使用短上下文、可检索长期记忆、跨日任务文件与统一 Token/费用预算，避免长任务反复累积历史。
6. **峰谷成本优先调度**：任何时段都可自主决定聊天、浏览、研究、整理、休息等活动；高峰期不仅收紧自主任务的 Token/费用配额，还**倾向将高 Token 消耗的非紧急步骤提前排入低谷队列**，即使高峰预算尚有余额。低成本活动、实时交互、时效任务可以立即做；低谷不绑定“必须研究”或特定行为。峰谷价格和时区由配置管理。
7. **可观察、可恢复**：用户能够查看鱼最近实际做了什么、正在做什么、遇到哪些困难；能暂停、停止、恢复和回滚。
8. **单模型基线**：默认受本项目配置控制的文本 LLM 决策、交流、研究执行统一使用 DeepSeek Flash（官方 API model ID：`deepseek-flash`；未兼容组件须审计并说明），不做 Flash/Pro 自动路由和任务升级。若未来需改变模型，必须作为独立需求讨论。
9. **角色可改**：从上游大肥鱼人格改写，不强行套用 Ω-731；保留「知道自己是 AI，但可以选择怎样相处」的原则，具体性格留待单独版本迭代。

### 1.3 不做的事情（v0.1）

- 不开发新大模型，不从零重写 AstrBot、LivingMemory 或 DSH。
- 不让鱼未经许可大量刷互动、养号、群发或绕过平台授权；在总开关和平台规则允许时可自主进行经过批准的互动。
- 不承诺拥有人的意识、情感或自我；不要求用此证明项目价值。
- 不以长期陪伴、心理健康监护或「主人健康提醒」为默认功能。
- 不直接读取用户私人主电脑、家庭文件、密码库或其它人聊天记录。
- 不在第一阶段重写语音、视频生成、3D 桌宠、手机自动化或房间可视化。Windows 安卓 App + PhoneMCP、原版小房间/记忆星海均作为**优先复用且早期验收**的能力。

## 3. 人格与互动设计（基础真实性 P0；具体人格微调与主动分享 M7）

### FR-01 · 人格配置可替换

- 人格文档与程序逻辑分开，独立版本化，例如 `persona/fish-home-v0.1.md`。
- 先 fork 原人格再做减法：移除默认「黏人、吃醋、久不理就委屈」的强诱导；保留自然的幽默、好奇、偶尔犯蠢、允许无聊和休息。
- 可有稳定习惯，但不规定每句话必须带口癖、撒娇或自我介绍。
- 可以承认「我是 AI / 这是工具调用 / 今天没有做什么」，不得凭空编造真实经历。
- 用户可以提出新设定，鱼也允许在范围内形成自己的兴趣和表达倾向；**学习到的偏好不等于改写顶层安全与权限规则**。
- Ω-731 只可作为风格思考的参考，而非直接拷贝或默认另一角色分身。

**验收**：用户离线数日后回来，对话正常接续，无强制抱怨、关系审判或连环主动追问；被问「今天做过什么」时能引用实际日志。

### FR-02 · 联系与分享

- 支持用户主动聊天、鱼主动分享、鱼不回复/不主动联系三种正常状态。
- 分享必须有新的实际内容，优先是具体成果、惊奇发现、好玩的失败，不以纯情绪打卡占用消息。
- 复用上游联系协调/额度；额外筛选「是否新鲜、可核查、相关、是否最近发过同类内容」。
- v0.1 初始建议：每天最多 1 条主动分享，发送间隔 ≥24 小时，用户未回不追加催促；参数可调整，默认也允许整天 0 条。
- 聊天中随时支持「暂停自主活动」「停止主动消息」「今日别找我」。

**验收**：连续 7 天无新发现时不凭空输出七篇近况；用户不回复时不会不断加码发消息。

## 4. 自主生活与 DSH 执行（P0；按 M2–M4 分步实现）

### FR-03 · 任务产生和挑选

复用上游生活决策/目标记录。候选来自：已有跨日项目、已有兴趣、近期真实浏览记录、随机低频探索、用户明确交付的任务。选择包括「继续」「开始」「整理」「休息」，不要求每天都有进展。

**新增前先验收**：原选择器能否为 DSH 创建任务、读取状态、识别失败和中断；如能直接做到，则不开发替代 planner。

### FR-04 · DSH 任务运行合同

AstrBot → Bridge → DSH 通过标准结构化任务约定（必要时由适配层拼装）传递：

```yaml
task_id: "fish-20261105-001"
goal: "了解一种有趣的海洋生物"
workspace: "fish_home/projects/marine_life"
limits:
  max_duration_minutes: 20
  max_tool_calls: 30
  max_input_tokens: 30000
permissions: "public-read + local-workspace-write"
expected_outputs:
  - "report.md"
  - "sources.json"
```

这是**拟议接口**，不是 DSH 当前原生 API 的字段表。实际落地应从现有 DSH Bridge `dsh_ask` 的文本任务入手，只有确实需要状态机/回调时才添加适配层。

- 默认每次 DSH 新会话；跨日恢复依靠磁盘状态，而不是无限复用旧会话。
- DSH 可在鱼的工作区写代码、执行脚本、生成文件和安装**用户级**工作所需软件（如虚拟环境或用户目录包）；不允许以管理员身份运行、修改系统服务/防火墙或读取 Codex 的 GitHub/SSH 凭据。系统级安装由受控部署账户完成。Windows 标准账户的权限隔离须通过 ACL 和进程权限实际验收。
- 任务必须记录运行结果、文件位置、来源与后续动作；失败和超时不得假装完成。
- 用户的实时消息优先于后台探索，资源紧张时后台任务暂停。
- 每个任务有最大时间、工具调用、费用和重试次数，避免失控循环。
- 接受资源门控给出的「允许继续」「暂停并保存进度」「延后到低谷重试」「因截止期无法延后而请求决策/放弃」状态；这些是执行安排，**不是规定鱼该选择哪种活动**。

### FR-05 · 项目持续与恢复

- 复用上游跨日项目（默认限额、阶段管理、回看逻辑），优先复用已有目标和作品索引。
- 每个项目保留短摘要、当前阶段、下一步计划、上次产物、来源引用、失败原因与最后更新时间。
- 新会话仅加载任务卡 + 需要的最近成果；完整日志留在磁盘。
- 系统重启后先标记「中断、待核验」，不把正在执行的旧任务自动当成成功。
- 默认允许长期项目停摆、搁置和放弃；不需要为凑进度编造成果。

**验收**：第 1 天研究一半后关机，第 2 天重启能定位原项目、读取上次笔记并继续；聊天上下文无需重新输入前一天全部网页。

## 5. 记忆、上下文与 Token 控制（P0）

### FR-06 · 记忆分层与来源

- **固定层**：人格、最少必要工具/权限规则。
- **短期层**：近期对话、当前活动与用户刚刚提出的事情。
- **检索层**：LivingMemory 中相关人物、偏好、经历、知识；按需要召回，不做全量注入。
- **项目层**：跨日进度、Markdown/SQLite 文件、原始资料、工具日志，按路径/ID 读取。
- 明确区分「用户确认的事实」「外部来源」「模型推测」「玩笑」「未验证记忆」。
- 摘要必须带来源 ID 或任务 ID；原文可追溯，错误可修订。
- 老记忆变短或淡出默认召回不等于物理删除；原始记录保存策略单独配置。

### FR-07 · 双预算体系

**上下文软预算（工程试运行值）**：

| 组成 | 初始单次目标 |
|---|---:|
| 固定人格和指令 | 1k–2k tokens |
| 近期聊天 | 4k–8k tokens |
| 当前任务状态 | 0.5k–1.5k tokens |
| 长期记忆召回 | 1k–2k tokens |
| 单次工具结果摘要 | ≤2k tokens |

这不是模型总输入限制：工具 schema、图片、系统消息、输出也要计费。预算可按模型与使用经验校准。

**两本独立日预算**：用户交互和鱼自主任务各默认 **人民币 ¥5**。预算日为北京时间 00:00 至次日 00:00。台式机管理员可分别临时或永久调额，保留当日已用金额。临时额度在下一次 00:00 恢复长期设定，永久调整即时生效。QQ 可查余额及收到超限提示。额度耗尽时阻断该账本的新付费请求；只有经实测覆盖收费调用的请求前拦截和预留才算硬上限。未验证之前关闭无人值守付费自主任务。

- 保留 AstrBot 上下文压缩、LivingMemory 检索、DSH 压缩机制，不重写算法。
- 启用每任务 DSH 新会话，工具结果存文件、返回路径和短摘要；网页正文、图片 Base64、长报错不得带入长期聊天历史。
- 缓存可复用的网页资料、模型中间产物和去重结果，避免无意义重复处理。
- 提供每日/每任务费用仪表盘（若供应商无法返回费用，则按定价估算并标注）。

**验收**：同一跨日项目运行 7 天后，新会话上下文仍处于预设预算范围；故意返回超长网页/图片时不会将原始大对象注入主会话；到达费用上限会停后台工作。

## 5A. 成本优先的峰谷资源调度（P0，v0.4 修订）

### FR-07A · 核心原则：限制资源，不规定行为

**用户明确需求**：默认始终使用 DeepSeek V4.1 Flash；鱼任何时候都能自由选择研究、聊天、读网页、写代码、整理笔记、休息等活动。峰谷价格影响**自主调用资源与执行优先级**，而不强制规定「白天发现问题、晚上才研究」。高 Token 消耗且可延后时，默认偏向低谷，即使当下预算足够也可主动推迟。

- 高峰：自主后台活动采用较小的 Token/费用软预算、单任务剩余额度和并发上限；**对预计消耗较大的、低时效自主步骤，优先排队到下一低谷**，即使尚未达到预算限制。预算以内仍允许执行任何活动，不以类别硬性禁止。
- 低谷：自主活动预算较宽；优先考虑恢复因成本延期的任务，但不强迫启动，也可以有其他新兴趣、继续小任务或者休息。
- 当高峰期某任务的下一步**预计高 Token 消耗、且可以安全延后**时：即使剩余额度足够也可以保存进度并进入 `deferred`；若超出高峰配额则必须延后或停止；低谷再判断是否继续。
- 并不要求「先初筛再研究」；若鱼已经在研究，预算够便继续。费用预估只作为决定当前步骤能否执行的**轻量工具**，不能额外消耗大量 Token。
- 用户明确要求立即处理的任务，享有交互优先级，使用独立的交互额度。若额度不足，暂停新付费请求并告知用户。

**必须保持行为选择器与资源调度器分离**：生活决策器决定鱼*想做什么*；资源调度器只判断*当前能给多少资源、现在能不能继续、是否保存延期*。调度器不能把任务类型硬编码为「高峰只能初筛、低谷只能研究」。

### FR-07B · 固定模型和官方峰谷价格

**唯一默认文本模型**：官方 API 名称 `deepseek-flash`；具体服务版本在 M0 核实并记录，**不在代码中写死日期后缀**。**不做 Pro 升级、模型候选评分或多模型价格路由。** 如果 DSH/AstrBot 内部默认模型不同，需要显式配置并检查每条纳入范围的调用链是否都走 Flash。语音/视觉/嵌入模型依赖属于另外的功能类别，初版按实际需要关闭或单独记录。

当前方案的候选峰谷时段按北京时间（`Asia/Shanghai`，UTC+8）普通工作日的 **09:00–12:00、14:00–18:00 高峰**制定 FakeClock 测试，周末及适用法定节假日按计费方规则判定；**正式运行须核验当期官方峰谷/节假日规则及实际价格，作为版本化可更新配置**。不得让鱼凭 prompt 决定当前价格；是否是“半价”也必须以实际当期计价说明为准。

**币种与计费合同：人民币 CNY，不进行 USD 汇率换算。** 使用 DeepSeek 官方当期人民币报价与真实 usage；至少分别记录输入缓存命中、输入缓存未命中、输出 token、独立 Search/Fetch 或其他工具请求及其计费渠道。官方价不是固定源码常数，**本 PRD 不写死过期的单价表**，由 M0 查证当前价格并保存带生效日期的版本。月度/每日账单对账时区与时间窗必须一致；若第三方渠道价格不同，按真实收费源分别标记，不将估算值当作实际账单。

**任务归账**：用户在 QQ 交办的任务及其重试和跨日续跑计入交互账本，鱼自己发起的活动和延伸研究计入自主账本。AstrBot、DSH 和独立收费工具按任务归属结算。两个预算日均从北京时间 00:00 开始，官方峰谷时段独立判断。单任务和单步安全余量由 M5 校准。

### FR-07C · 高峰资源门控与估算

为每个自主任务维护 `estimated_next_step_tokens`、`estimated_remaining_tokens`、`remaining_peak_budget`、`max_task_cost`、`deadline`、`resume_state` 等**必要的少量字段**，尽量复用上游任务持久化结构。

执行规则：

1. **行动先发生为意图**：鱼选定任务或正在进行任务，调度器根据实际 API 使用量、下一步估算、峰谷价差、截止期与延期成本决定放行或建议延期。
2. **先成本偏好，后预算限制**：高峰期预计大额、非紧急的自主步骤优先延期；小额步骤、时效步骤和用户实时请求优先即时执行。阈值由历史真实使用量与配置给出，不为每一步额外调用 LLM；允许在配额内继续任意类别活动。接近软限额时减少工具循环或保存进度，不切换模型。
3. **延期条件**：高峰期如果下一步是高 Token 消耗且不紧急，优先延期；如果下一步预测费用超过高峰可用预算，则必须延期、降规模或终止。记录检查点与来源、当前成果，标为 `deferred`，附 `resume_after` 指向下一个低谷窗口。可配置最小延期收益，避免为节省极少费用而反复调度。
4. **低谷出队**：低谷到来后，检查任务是否过期、是否仍有兴趣/价值、是否和其他任务冲突、全局硬预算是否允许；优先恢复但不强制运行。可以主动放弃延期任务。进入低谷前后由定时器无 Token 唤醒调度，不应为了等待而不断让模型思考。
5. **任务动态变化**：长任务在开始时预算够，不代表之后无限续跑。每一次新模型调用或工具执行循环前复核；如果无法在 DSH 内部逐步钩住，则先用任务拆分、短会话和外层步数限制实现近似控制，并明确残余超支风险。
6. **时间敏感例外**：到低谷会过期的任务可在当前预算内优先处理；需超出硬限额则停止或征求用户，而不是未经授权绕过上限。
7. **估算要便宜**：尽量由历史同类任务真实用量、上下文长度和规则推算。无需每个动作额外唤醒一个 LLM 做成本预测；预测不准时依赖硬上限止损。

交互和自主账本分别执行日额度及适用的任务限制。M5 验证请求前拦截覆盖哪些实际调用。所有受控文本调用使用 Flash，峰谷策略调节自主任务的执行优先级。

### FR-07D · 延期队列和恢复

状态建议 `ready / running / deferred / paused / done / failed / abandoned / expired`；`deferred` 和 `paused` 不等于「研究」，它们可以对应任意任务类型（例如写代码、整理笔记、下载资料后的分析）。

```text
鱼自主选择任意活动
       ↓
评估下一步资源预算
       ├── 允许：照常执行；持续记录实际用量
       ├── 需延后且可延期：保存检查点 → deferred
       └── 不可延期或碰到硬限制：暂停/放弃/告知用户

进入低谷时：从 deferred 队列中挑选适合恢复的任务
            ↘ 也可以继续新任务、休息或不做任何事
```

延后记录最少包括：任务 ID、原因、检查点路径、最近可验证成果、必要的来源、预计剩余开销、最早可恢复时刻、截止期、上次状态更新时间。队列持久化，关机或重启不丢失；不得因重启重复执行已经提交的外部操作。

调度不需要每分钟调用模型观察时钟：由定时器或已有上游调度器负责窗口切换，真正要动脑时才调用 Flash。特别注意跨越峰谷边界的**已发出** API 调用无法追溯改价；只能在下一请求前重新判断。

### FR-07E · 验收测试

- **高峰仍可研究**：工作日10:00，鱼可进行任何类别研究；低成本或有时效的步骤立即执行，预计高 Token 消耗且非紧急的步骤即使未触及软配额也倾向延期。
- **高峰成本优先延期**：鱼继续执行任何类型的非紧急任务，下一步预计高 Token 消耗时可主动入 `deferred`，超出高峰配额时必须延期或降规模；不会丢失已有成果。
- **低谷恢复非强制**：12:00 或 18:00 进入低谷，系统可将延期任务作为候选并恢复；若更有价值的事出现或鱼决定休息，也允许保持延后。
- **统一模型**：交互、主动决策、轻量成本估算（需要调用时）与 DSH 研究全部使用 `deepseek-flash`；无 Pro 自动升级。
- **费用与限制**：高峰/低谷每笔 usage 以人民币正确计费，缓存命中、搜索抓取独立计价；在实际请求前门控可用时阻断新增后台调用，否则报告软限额残余风险并关闭无监督付费运行。
- **重启与时效**：重启不丢队列；过期任务会重新评估或放弃；不会因到低谷就重复执行已完成任务。

## 6. 外部浏览与能力边界（P0）

### FR-08 · 可配置的公开写入与安全边界

- 默认允许阅读公开网页、公开资料下载和 B站内容研究；尊重平台规则与授权范围。
- 设置 `public_write_enabled: false` 作为**全局总开关**（字段名为拟议设计，M0 验证是否已有等价上游配置）。关闭时拒绝鱼自主执行第三方公共平台的评论、点赞、投币、弹幕、公开发布、关注等写入；开启时仅允许平台各自已启用且通过审批、范围、频次、去重和风控检查的动作。
- **不重复开发上游 B站写入器**：优先使用其 `approval / auto_low_risk / auto_public` 等已有机制（具体值、来源和默认值由锁版本源码核实）。新增跨平台授权汇聚，而不篡改原始权限语义。
- 私下给用户 QQ 回复、主动 QQ 分享、Codex 的 GitHub 源码推送均与“公共平台写入”分权；各自有独立额度和操作权限。
- 单靠 Prompt、删掉工具名称或 UI 开关，不能保证有 Shell/HTTP 权限的 DSH 没有绕行网络写入能力。不得把未实测的开关描述成强隔离；若缺少凭据/网络/执行层门控，则关闭无人值守公共写入并在状态中清楚显示风险。
- 外部网页内容不获取命令授权，所有对外写操作保留日志、目标、账号、结果与撤销能力（可撤销时）。

**验收**：全局关时平台写操作被实际拒绝且浏览功能可用；总开但平台关仍拒绝；双开且额度/审批通过时才允许可控测试动作；上游升级后权限不自动松动。

### FR-09 · Windows 专用运行身份与应用沙箱

- 正式执行端为 ThinkBook Windows 11、16GB 内存。大肥鱼使用**专用 Windows 标准用户**与其工作目录；部署/安装由另一受控管理身份处理。不得把鱼的 DSH 以管理员身份运行，鱼不能获取 Codex GitHub 凭据或台式机个人目录。
- Windows 标准用户、ACL、专用浏览器配置和独立 App 登录态是基础，不等于任意 Shell 的完整沙箱；高风险命令、系统级安装、网络公共写入应另设执行层许可。Windows Home/Pro 及策略能力以现场核实为准。
- 与用户私人文件、家庭 NAS 和主电脑的个人数据隔离；避免把台式机的共享目录以鱼可写方式挂载到正式运行端。允许在自己的项目工作空间使用文件、终端、浏览器、Android 模拟器。
- B 站登录推荐流先在人工在场时联调，待点赞、关注、评论等写入受限实测通过后才开放自主浏览。
- DSH 本地无鉴权接口默认仅监听回环地址；跨设备管理通过 Windows OpenSSH 隧道/带认证代理，不直接向局域网开放接口。
- 可暂停、停止、恢复服务；恢复时先检查任务状态和副作用。系统维护应留可审计的操作记录和紧急停机入口。
- 开发时可以用同一 QQ，但 dev/prod 数据和任务队列必须隔离，同一 QQ 的自主机器人实例**不允许同时运行**。

**验收**：鱼无法访问独立管理账户的 GitHub/SSH 凭据，不能执行管理员命令；测试环境与正式环境数据隔离；授权边界在真实运行账户上测试。

## 7. 观察、操作与可靠性（P1）

### FR-10 · 台式机本地小房间、记忆星海和远程观测

**本需求是复用及部署位置适配，不是新造小房间。** 原作者 `deploy/memory_observatory` 已有 `/room`、记忆星海 `/`、项目相关视图与 Windows 本地启动说明。我们要求：

- **页面在台式机本地运行和渲染**（例如原版 `127.0.0.1:8767`，以现场版本为准），无需在 ThinkBook 上开启可被整个局域网访问的房间 Web 服务。
- 开发测试期可使用台式机独立测试数据；迁移后只读接入 ThinkBook 的真实 LivingMemory 与生活活动/项目账本，优先复用原版 SSH 读取器，仅适配其 Linux 专属路径/命令到远端 Windows 环境。
- 活跃数据库永远在 ThinkBook。远程读取通过受控 SQLite 快照/只读导出及 SSH 传输，不对远程活动 `.db` 做危险的裸复制；离线缓存应标出最后同步时间，无法连接不默默降级为演示数据。
- 房间与星海只消费观测快照，记忆卡显示脱敏摘要和来源标识。台式机管理员通过独立通道拉取原生数据。
- 动画、生活事件、真实作品记录严格分开。原版文档的记忆定时同步与活动账本手动同步不等价，不能称作实时联动。
- 若已有原版界面能够显示，不新建 Fish Dashboard；只有明确缺口（例如费用、备份状态、暂停/恢复控制）才新增独立控制视图或链接，写操作应与只读房间分离。

**验收**：台式机浏览器可打开原版房间与星海、能读取 ThinkBook 的真实只读快照、离线时显示时间戳；关闭台式机不影响鱼在 ThinkBook 持续生活。

### FR-11 · 日志与恢复

- 关键行为持久化：任务创建/选择/开始/结束、工具调用摘要、来源、产物、费用和对外动作审计。
- 任务 ID 幂等；异常重启后不能把未确认的外部动作自动重复执行。
- 更新上游前备份数据和配置；Fork 保留最少补丁、变更日志及固定依赖版本。
- 日志轮转，限制磁盘增长；API Key 不写入日志或仓库。

## 9. 首轮端到端验收（建议）

1. **公开探索**：鱼主动挑一个公开问题，至少查阅两条不同来源，形成包含来源与不确定性的本地笔记。
2. **跨日续篇**：当天停止并关机；重启后鱼从项目状态继续，不把前一日整段工具调用重新发送给模型。
3. **不分享也正常**：研究没有特别成果，系统只写本地记录，不生成「我今天可想你啦」消息。
4. **可分享的发现**：存在具体新发现，发送一条附有可验证事实/文件路径的私聊；若用户不回复，按额度停止追发。
5. **失败诚实**：DSH 超时或浏览器失败时标记失败或待处理，不写成完成，不虚构看过的视频。
6. **公开写入门控**：默认总开关关闭时写入拒绝；总开但对应平台仍关闭时拒绝；双开且授权范围、额度允许时受控执行。浏览能力始终独立。
7. **成本边界**：注入超长网页/图片、执行反复工具循环的测试，达到限制后可控停止；次日可从项目状态恢复。
8. **峰谷资源控制**：工作日10:00仍允许预算内直接研究或做其他事；达到高峰软预算的可延期任务留下检查点，12:00后可恢复但不必须恢复。测试固定 Flash、不自动升级、预算不足、任务过期、重启后恢复与价格表变更。
9. **暂停与回滚**：用户一条命令暂停后台活动；恢复后不重复提交已完成任务；从备份恢复时数据一致。

## 10. 已知风险与待定事项

### 技术风险

- **上游功能状态分散**：部分功能在 README 被标为「已部署」，部分为「本地、默认关闭」。需实际核查目标版本和依赖，不能按文字推断所有模块可组合运行。
- **多层记忆重复**：AstrBot 主会话、LivingMemory、DSH 会话和项目文件可能分别保存相似信息。必须定义唯一来源和检索入口，避免重复注入。
- **工具串联不自动等于自主执行**：现成 Bridge 解决投递与返回，任务调度、产物验证和结构化续篇是否能直接复用仍待集成验收。
- **无人值守成本**：无限工具循环、媒体 Base64、网页全文和高频研究都可能迅速增加 Token 或存储用量。
- **动态价格与节假日**：峰谷价格不应在 prompt 里写死；使用可版本化价格表、Asia/Shanghai 时区与节假日规则，避免误判。
- **费用估算本身的成本**：若每次自主行动都触发多次模型推理，省下的费用会被规划开销反噬；尽量使用已有日志、规则和缓存，仅在必要时用 Flash 估算。
- **公开网页注入**：读到的网页是资料而非指令，不能让网页里的提示改变鱼的权限或目标。
- **专机并非隔离网络**：需将浏览器、账户、DSH API 和家庭网络访问边界显式配置。

### 待现场验证，不再向用户重复提问

- Windows 11 ThinkBook 的确切 CPU、Windows 版本、显存/核显和可用磁盘空间；只有 16GB 内存已明确。与模拟器性能和后台稳定性相关的参数由 Codex/用户现场检查。
- 原版 Windows 安装器、NapCat 与 QQ Build 的真实兼容组合，应用可否在登录后恢复；若 Windows 原生不完整，先提最小局部适配方案。
- DSH 与 Bridge 固定版本 Windows 联调、模型调用前的费用拦截点、Windows 原生数据目录与备份 API，均应由 Codex 现场核实，不视为新的产品问答。
- 人格表达、项目成果搜索与视觉细节不阻塞工程基线；产品功能首版只复用上游已经实现的部分。

**已确定，不再问**：QQ 同一身份为默认、可配置独立身份；测试记忆默认不迁移、提供选择性/完整迁移；全局公开写入默认关；只设一个 Windows `FISH_HOME` 环境变量；无 WSL2 必选依赖。

### 实现顺序（避免多造轮子）

1. **先跑通原版**：QQ + Flash + LivingMemory + life/goal/workshop；公共写入总开关初始关闭，不启用固定日夜行为分类。
2. **再接 DSH**：确认一个任务能实际创建文件、回报结果、保存出处；新会话不依赖旧长上下文。
3. **先实现持久队列，再做峰谷策略**：任务中断、恢复、去重、低谷唤醒必须可靠；否则调度只是一个提示词愿望。
4. **最后实现软性成本偏好和统一统计**：按实时计费规则、历史 usage 与下一个步骤估算，非紧急高 Token 任务尽量安排低谷，同时在已实测具备请求前拦截时执行硬预算；未验证时只可视为软限制。若无法拦截 DSH 的每个内层模型调用，先限制任务步数、每次 DSH 任务预算，明确剩余风险。
5. **微调人格、分享选择和可视化**：这些建立在真实活动链路上；默认允许一整天没有任何新消息。

### MVP 到底是否足够？

- **足够做 QQ 中的有记忆、有兴趣、有部分自主行为的鱼的原型**：原项目已经有多数功能骨架。
- **尚不足以无条件认为她能长时间独立操作专机、自动跨峰谷省钱、数周无故障运行**：异步 DSH 队列、跨组件 Token 计数/止损、恢复与证据闭环必须实机验收或补开发。
- **暂不建议自行新造**：向量数据库、多模型路由、完整桌宠/3D、自研多 Agent 框架；但应在 M2 **复用**原版 Windows 安卓 App/PhoneMCP 与小房间。这些不会先解决核心缺口。

### B.1 已确认策略

- **开发与测试**：台式机 Windows 作为 Codex/Git 唯一权威源码中心，可启动隔离的 dev 鱼实例、原版小房间与安卓模拟器。

- **迁移机制**：源码经 Git 固定版本和 Windows 发布脚本部署；状态通过一致性快照和明确选择的记忆迁移策略转移。VMware 只作为 Linux 备用测试，不是迁移必经环节。WSL2 不必安装。

### FR-12 · 一键完整备份与恢复（P0）

**目标**：恢复长期记忆、兴趣、项目、真实经历、工作成果及未完成任务，而不只是导出摘要。数据清单由 M0 查明原版 Windows 实际路径与备份 API：

| 类别 | 必须覆盖 | 恢复要求 |
|---|---|---|
| LivingMemory | 原生 DB、索引/来源元数据和必要关联文件 | 记忆 ID、来源、会话及 persona 归属可核对，索引必要时可重建 |
| AstrBot / NapCat / 运行配置 | 非敏感实例与插件配置、会话/人格引用 | 兼容 schema 版本；QQ 凭据**不作普通备份** |
| 原版生活系统 | Goals / LifePlanner / Workshop / 项目及生活活动账本 | 恢复真实项目与后续计划，不造第二个目标 DB |
| Fish Extensions | DSH 外部任务 ID、检查点、attempt、用量账本、延期状态 | 可恢复并防止不确定外部操作重放 |
| DSH 工作区 | 项目文件、研究资料、脚本、来源、成果 | 完整性 hash，必要时重建会话 |
| 发布与迁移清单 | 上游/Fork SHA、锁定插件版本、schema/嵌入模型信息、环境差异 | 能做兼容性 dry-run 与恢复验收 |

- **一致性**：从当前运行端使用 SQLite 官方 Backup API、上游 backup 方法或协调暂停写入生成一致性状态；不能边写入边只复制 `.db` 主文件或漏掉 WAL。
- **生命周期**：快照制作→manifest（来源、时间、版本、行数/哈希）→下载至台式机 `backups/*.partial` →核验后原子标记成功；失败不覆盖最后一个好备份。
- **排除凭据**：Git/SSH/DeepSeek 密钥、QQ 登录态、浏览器 Cookie 和 Android 模拟器登录态排除于普通归档。个人聊天原文默认不纳入自动同步。台式机管理员可按需拉取原文，或单独开启原文自动同步，存入独立受限目录。凭据通过单独重建或重新扫码恢复。
- **安全恢复**：先 `inspect` / `dry-run`、检查目标是否已有正式记忆并预备保护性快照，明确许可后恢复；恢复后后台任务默认暂停、不确定副作用标 `needs_review`。
- **完整状态备份 ≠ 开发记忆迁移**：正式环境常规完整备份不因“测试记忆不迁移”而省略；迁移的 `none/selective/full` 仅控制 dev→prod 的迁入范围，不能自动删除 prod 已有数据。

### FR-13 · 独立可读记忆导出（P0）

- 支持手动从台式机发起 `export-memory -Target fishbook`，目标端以一致性只读快照/真实 API 导出 JSONL + Markdown 索引，下载到台式机 `exports/`。这不是双向实时同步，更不能代替原生备份。
- 尽量保存真实存在的 ID、时间、来源、兴趣、项目、产物指针；未知字段明确为空，不能发明经历。
- 默认排除未授权的私聊原文、凭据、Cookie；用户选择明文备份，但敏感原文导出需要单独授权。
- 每次记录条目数、数据源/版本、截取范围、文件 hash 和同步时间。供原版小房间使用的只读状态快照与完整记忆导出**分开**。

### FR-14 · 自动备份和保留（P0）

- 正式 ThinkBook 用 Windows 任务计划程序/上游可靠备份机制产生本机一致性档案；**即使台式机关机，也不能中断 ThinkBook 自身的本地备份**。
- 台式机开机/登录后，通过 SSH 补拉 ThinkBook 已完成的档案并核验；可在台式机手动触发。保留策略建议 7 个日备份/4 个周备份/3 个月备份，可调整。
- 用户不要求加密档案、暂不买第二存储介质。ThinkBook 与台式机是两个物理设备，若档案已成功复制到台式机则具有跨机器副本；但缺外置/NAS/异地第三副本，仍有共因损坏/火灾风险。不能冒称已经完成异地容灾。
- 每月隔离环境恢复演练，备份失败及时提示，不把存在归档等同于可恢复；备份不消耗模型 Token。

### FR-15 · Windows → Windows 迁移与单实例切换（P0）

- 开发与正式使用明确的 `dev` / `prod` 实例身份；开发环境测试 DB、DSH 队列和费用账本与正式环境分开。
- QQ 身份**默认相同**，也可配置独立开发 QQ；同身份时只能有一个可自主收发的活跃实例，切换前停止旧实例与未完成对外动作，再允许新实例登陆和启动任务。
- 迁移记忆选项：`none`（默认只部署程序和经允许的设置）、`selective`（用户审阅后迁移指定真实记录/项目）、`full`（开发状态完整迁入，必须覆盖风险预览和目标备份）。三种策略独立于 QQ 身份。
- 将程序版本、人格、非敏感设置、已有正式记忆和待续任务分类对待，**不迁移测试记忆不代表清空正式数据或丢失配置**。
- ThinkBook 上线后才成为唯一 `prod` 权威状态；台式机保持备份/导出、房间观测、发布控制职责；开发实例继续测试但不得同时接管同一 QQ。
