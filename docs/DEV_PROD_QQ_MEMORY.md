# 开发/生产隔离、QQ 身份与测试记忆迁移 v0.7

## 两个独立开关，而不是固定唯一选择

| 配置轴 | 默认 | 可选 | 不变量 |
|---|---|---|---|
| QQ 身份 `qq_identity_mode` | `shared`（同 QQ） | `separate`（开发 QQ 独立） | 同一 QQ 只允许一个自治鱼实例活动；登录态与扫码由用户管理 |
| 迁移记忆 `memory_migration_mode` | `none`（测试记忆不迁移） | `selective` 或 `full` | 不能因未迁移而删除正式记忆；不能偷偷混合两个 live DB |

**上述字段名为设计示例，不是上游实际 config schema**。由 Codex 查上游配置并封装。选择不同 QQ 与迁不迁记忆没有必然关系，不应绑在一起。

## dev → prod 发布

1. 检查目标 prod 当前状态，若有正式数据必须**先做目标一致性备份**；记录版本和需要重新配置的账号登录态。
2. 停止台式机 dev 机器人与自动任务，若共用 QQ，确认不会与 ThinkBook 同时使用该身份。不得让同账号两个实例抢消息或重复提交公开动作。
3. 部署通过测试的 Git SHA 和非敏感配置。`none`：不复制开发记忆；`selective`：逐项预览记录/项目、来源和冲突，必要时用插件官方导入接口；`full`：完整导入需有差异报告和覆盖确认。
4. QQ 需要重新扫码时由用户在目标环境操作；常规备份不迁移 QQ cookie、账号设备指纹或 Android 模拟器登录态。
5. ThinkBook 上线后保持后台自主付费任务和公共写入默认暂停/关闭，先检查真实 DB、费用账本、活动状态、PhoneMCP，再开启生产工作。
6. 台式机仍可开发独立 dev，但如共用 QQ，不能启动两个可收发自主任务的实例。dev 费用、实验数据与 prod 账本永不混记。

## “不迁移测试记忆”不等于“不迁移任何设置”

可按类别选择迁移：Git 内版本化人格、上游配置模板、工具绑定、系统 prompt、原生记忆、跨日项目、研究成果、可读导出、模型 usage 账本、QQ/Android 登录态（默认**不迁移**）。每类有明确 owner/风险/来源，不能用一个“复制 data 文件夹”覆盖所有选择。

## 测试矩阵

- shared QQ：dev 运行时阻止 prod 收发/自发任务；切换失败可恢复旧实例而不双开。
- separate QQ：不同号码可在逻辑上并行，但 dev/prod 状态仍隔离、不要共用写入数据库。
- none：新的 prod 从原有正式 DB 或干净 DB 开始；保留非敏感系统配置。
- selective：项目/记忆来自真实记录且带来源、冲突可提示。
- full：目标原有正式 DB 不得无确认覆盖，恢复后已完成任务不重复。
