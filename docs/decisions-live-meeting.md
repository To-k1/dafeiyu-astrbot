# 组会实时会场决策

| 决定 | 理由 |
| --- | --- |
| 在现有控制台的「近期组会」进入会场，ThinkBook 本机和台式机远程控制台查看同一场。 | 保留已有的组会入口和远程访问方式。 |
| 实时会场和历史回看共用页面，显示完整发言及等待、思考中、已发言等状态。 | 直播与回看使用同一份会议记录，避免另建一套历史。思考中只表示执行状态。 |
| 观看不触发发言或推进会议。主人点击发送才会写入一条带署名的插话，并在下一条可接收新内容的发言前生效。 | 保留会议原有调度和 QQ 汇报规则，让参与者能区分主人的原话和主持人的总结。 |

| 已开始的并发发言照常完成。尚未发出请求的成员能在当前轮接到主人的插话，之后的发言也可看到它。 | 插话可以及时进入讨论，保留已经进行中的发言。若散场前没有成员确认接收，页面留原话并标明状态。 |
| 首版只做观看、回看和主人插话。暂停、结束、改议题由现有入口处理。 | 会场只需要展示和发送普通发言，复用现有主持控制。 |
| 「茶会」和「闲聊」都对应现有的 `casual` 类型。 | 主人可以自然描述想开的会，旧记录和工具参数沿用原格式。 |

2026-11-21 确认按此方案实施。

### 共用会场

| 决定 | 理由 |
| --- | --- |
| 控制台首页自动显示进行中的组会，无进行中组会时保留最近一场入口。「近期组会」自动更新。 | 新会能及时发现，短会散场后也能从首页直接回看。 |
| 控制台会议链接、单独打开的标签页、控制台「DSH 会场」和 DSH 侧栏共用 `/meetings` 页面。 | 一份页面代码承担读记录、看实时状态和主人插话，布局与交互一致。 |
| DSH 插件注册原生侧栏和主面板，主面板嵌入控制台提供的会场。 | 复用 DSH 0.2.2-rc.1 的客户端扩展机制。控制台承接会场鉴权，FishHome 现有会议记录继续作为数据源。 |
