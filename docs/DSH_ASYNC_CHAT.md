# 普通小弟交谈的异步接收

## 发现的问题

此前 `df_dsh_chat` 在主人当前的模型调用中同步等待最多 75 秒。超时只返回 `unconfirmed` 并关闭 RPC 客户端，没有后台继续接收或回报。

具名聊天会先持久保存 `pending_chat`。后续再次调用时若它仍存在，旧实现只取旧请求的结果，跳过这次传入的新消息，并返回 `recovered_previous_turn: true`。这个字段不表示新消息已发出。`last_chat` 只是最近一次已确认成功的请求索引，不能替代完整 DSH 消息历史。

本次只读核查对应的原生 DSH 历史：501 字长输入已有 completed 终态及 1255 字回复；62 字短问没有成为独立 DSH 回合。因此，“第一次请求没有落库”和“短问重新让小弟作答”均不符合该记录。没有足够的实际耗时数据把延迟直接归因于人格长度或订阅额度。

## 修复后的使用方式

`df_dsh_chat` 始终异步，具名及默认单次交谈都立即持久入队。编号只供内部关联，不要求主人发送特定格式。

- `action=send`：保存新消息并返回 queued。已有未完成回合时，新消息独立排队，不会被当作查询丢弃。
- `action=get, chat_id=...`：只读查原提问、请求号、完整回复、状态和通知结果。
- `action=list`：查看最近聊天的状态。

同一小弟按顺序交谈，不同小弟可并行。后台使用原 request_id 继续接收长回合，75 秒只结束本次轮询，不再结束结果接收。重启后保留排队消息和在途请求；旧版遗留的 pending 可单独接管。没有原文且需重新发送的旧请求会明确进入待核对，不能凭空重写。

小弟回复正文和来源先写回现有 activity 数据库，再交给肥鱼本人。主人发起的聊天由肥鱼组织回报，走现有 QQ 持久待发队列；自主聊天只交给肥鱼，不自动向主人发送。肥鱼可以继续使用聊天工具回应小弟。通知失败保留正文和错误类型，QQ 重试复用同一幂等键；已经生成的回报文本会复用，避免仅因 QQ 掉线重新调用肥鱼。

等待 OpenCode Go 订阅额度的请求使用 Go 自身额度恢复判断。既有人民币账本和峰谷限制不套到 DSH 的 Go 请求；肥鱼自己理解回报仍走相应交互或自主计费入口。

## 状态和回滚

聊天使用 `queued / running / go_wait / completed / needs_review`；通知独立记录 `pending / sending / notified / uncertain`。进程恰好在通知过程中退出时，sending 记为 uncertain，避免把未确认的通知说成送达；原回复仍可用 get 查询。

新记录使用现有 activity.sqlite3 的 `dsh-chat:v1:<scope>:` 命名空间，不建立第二套人格或记忆数据库，不修改现有小弟人格。只读调查不花模型费用，不执行 QQ 发信。

2026-11-18 验证：1063 项回归通过、19 项跳过，覆盖聊天工具立即返回、跨轮和重启恢复、不同小弟独立通知、原回复保留、QQ 离线重试及主人作用域。正式 QQ 联合验收中，01:14:11 先告知发出，01:14:42 自动回报，主人未催取。后台对应 completed/notified，使用原小弟 v3 和原会话，只有一条新增 Go 回执、零额外尝试，完整小弟回复和肥鱼回报均已保存；主人确认收到。

回滚前暂停新增聊天，正常停止 AstrBot，恢复部署前的 `main.py` 与帮助页面。新增队列模块及记录可保留，不删除正式数据；旧代码忽略新的队列命名空间。回滚后尚未完成的异步消息不会继续自动派发，应先导出和核对。
