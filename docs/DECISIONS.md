## 开工前确认的执行口径

- **预算日与账本**：按 Asia/Shanghai 的 00:00 至次日 00:00 划分，交互和自主各默认 ¥5 CNY，官方峰谷时段独立配置。用户在 QQ 交办的任务连同重试和跨日续跑沿用交互归属，使用执行时所属预算日的余额；鱼自己发起的延伸研究计入自主账本。
- **调额与耗尽**：台式机管理端可分别调整两本账。临时额度在下一个 00:00 恢复长期设定，永久调整立即生效，均保留当日已用金额。额度耗尽时暂停该账本的新付费请求，QQ 可查余额及收到提示，聊天和任务工具无调额权限。硬上限须验证实际收费调用前的拦截和预留。未通过的收费执行路径保持受控，未验证前关闭无人值守付费自主活动。
- **安卓**：B 站登录推荐流先用于人工在场联调。限制点赞、关注、评论等写入的执行层实测通过后，才开放登录态的自主浏览。匿名公开内容可以通过只读路径使用。
- **观察与管理**：房间和星海展示活动、项目、研究成果和脱敏记忆摘要与来源标识。台式机管理员从独立通道按备份计划同步原生数据。私聊原文默认按需拉取，可单独开启自动同步，使用独立管理员目录。

- **M1 运行与 M2 QQ**：台式机 M1 使用当前 Windows 账户和独立的无凭据开发目录。M2 使用现有专用 QQ 小号，只接受一个管理员 QQ 的私聊触发，其余 QQ 请求在记忆、模型和工具调用之前忽略。

## 工程上需要现场证明，而不是再向用户提产品问题

1. ThinkBook 上 AstrBot Launcher、NapCat、Android 模拟器、PhoneMCP、DSH 及生活插件能否组合稳定运行；记录 QQ/NapCat 构建号与各插件 SHA。
2. 原版观测台 Windows 本地服务如何读取远程 Windows 数据；读者 SSH 接口是否假定 Linux shell/路径；是否能采用可靠只读快照。
3. DSH Bridge 和官方 DSH 固定版本的 Web/headless/浏览器/usage/cancel 兼容，是否能真正实现请求前硬预算。
4. Windows 11 SKU/CPU/硬盘/模拟器资源配额、GUI 登录后自动恢复；标准用户与管理员之间 ACL 及启动服务策略。
5. ThinkBook 的真实持久化目录/原版备份 API、数据库索引/文件协同时间点；远程备份/可读导出可恢复性。
6. 原版 B站互动总开关与各平台权限是否可在工具层执行；广泛 Shell 联网如何防止绕过。

这些写入 M0 审计报告，不在开工前要求用户提供不必要参数。真实账号扫码/Key 注入是首次实际联网操作时的人为步骤。
