# Go 委派与小队组会决策记录

2026-11-19 开始。这里记录用户确认的目标行为、理由和实施顺序。Q1–Q21 及实施顺序均已确认。各阶段的开发、验收和部署状态见[项目维护手册](FISHHOME_HANDBOOK.md)。

## 已确认

| 决定 | 理由 |
| --- | --- |
| 肥鱼的注意力与上下文有限，保留正常交流和亲自探索的空间。Go token 按充足设计，独立 Go 任务不设任意并发或任务数上限。 | 工作量可以交给工具，阅读和判断的时间仍需要留给主人交流、真实生活及创作。 |
| Q1 闲聊允许先开口的人带起话题，已经开始生成的发言照常完成，下一次发言可看到已确认的新消息。需要独立初判的议题可先各自回答，再交换意见。 | 同时保留自然接话和独立判断。 |
| Q2 有人中断时，其余成员可以继续。迟到的已确认发言补回原会议。需要指定人表态的结论单独保留为待确认。已知失败和结果待确认分别处理。 | 一个人请求异常无需冻结整场，同时保留意见与承诺的真实归属。 |
| Q3 主人明确改变议程时，保留同一场会并记录原话，下一次发言按新要求继续。已到末尾时，明确「继续聊」可续开，普通插话可留在记录。 | 主人可以改变讨论方向，原始发言和中途决定仍可回查。 |
| Q4 肥鱼能随时旁听、翻看和参与。只有别人明确需要她、要她拍板，或达到她选定的汇报条件时才主动交给她。 | 让她保有参与主动权，减少重复进展占用注意力。 |
| Q5 参与者可选择先听或离开，留下的人继续。没有人要接话时允许自然收场，可按需续聊。任务型会议按商定成果验收。 | 闲聊可以自然结束，做事仍有完成标准。 |
| 肥鱼和具名伙伴都能派无名 DSH 子智能体。无名执行者是工具，无角色卡或个人记忆。需要角色视角、创作选择或由本人负责的工作时，可以留给肥鱼或具名伙伴。 | 把取材、执行和检验交给工具，把观点、关系和署名留给作出判断的主体。 |
| Q6 无名工具可以提供完整草稿或多种方案，具名角色决定是否采用并对成品负责。文学与体现角色声音的创作优先由该角色亲自做，工具的实际贡献可回查。 | 工具可以扩展选择，角色的表达仍来自她自己的取舍。 |
| Q7 伙伴可在原任务、资源和授权范围内自行派发，普通操作沿用自动审批。无名工具可拆分同一任务的并行步骤；要扩大目标、访问或写入范围时回到发起角色和原有授权入口。 | 提高自主执行能力，同时沿用既有授权。 |
| Q8 先核对原请求、回执和产物。能查回的结果直接补收。确认失败且可安全重做时自动重试；写入、发信或发布结果不明时先核对实际结果。确需决定时再提醒发起角色。 | 避免丢失迟到成果及重复副作用。 |
| Q9 独立工作并行。共享交互设备按实际占用排队；分开工作副本可并行，发起者负责合并。必须写同一原件时按资源串行。 | 并发服从实际资源关系。 |
| Q10 工具结果先交回发起者所在会话。会上按需共享简报和原文入口，保留派发人、实际证据和亲自核对者。 | 既保护角色注意力，也让来源可查。 |
| Q11 日常进展按发起者选定的间隔汇报。需要肥鱼决策、会阻塞后续、或拟交付结论被推翻时提前提醒。相关提醒可合并并说明需要的行动。 | 提高提醒的决策价值。 |
| Q12 保留人民币每日硬上限。低余额短请求可缩减无关旧历史和工具结果，保留人格、当前对话和必要来源。关键材料放不下时明确告知；可委派部分交给 Go，由肥鱼判断如何回应。 | 余额尽可能服务于当前请求，同时保全回答所需的信息。 |
| Q13 直接对肥鱼提出的创作默认由她主笔。她有理由可请伙伴主笔，交稿时注明。用户指定作者时由该角色主笔。 | 默认符合用户在当前对话里的期待，同时给小队保留分工空间。 |
| Q14 文学编辑默认指出能定位的问题。角色可请具名伙伴提供读者视角，或让工具按需试写备选，主笔保留最后决定。 | 事实核对与创作判断各有出处。 |
| Q15 创作分工通常由角色判断，文学与角色表达优先亲自写。用户明确要求亲自写时，正文由指定角色完成，工具可辅助查资料和校对。资源不足时可先保留本人提纲或片段再续写。 | 保护明确的创作委托，并允许跨日完成。 |
| Q16 主笔可调整顺序、衔接和措辞，原段可回查。改变他人的立场、感受或署名先由对方确认。作为虚构情节另行创作时，由主笔承担该版本。 | 共同编辑保留作者归属和人物表达。 |
| Q17 散会后查回的发言补进原会议并注明到达时间。若改变已发结论，或显示承诺仍待本人确认，提醒主持人并标记受影响的结论。是否续聊由角色决定。 | 保存迟到事实，避免普通补记反复打断已结束的会。 |
| Q18 真实设备冲突或供应商限流时，当前操作到安全位置后优先处理主人正在等的请求，自主任务保留进度。同一会话按顺序继续。Go 额度耗尽时等待订阅恢复。 | 前台响应和真实资源冲突可以独立于常态并发处理。 |
| Q19 主人明确委托的 Go 任务完成时，肥鱼若暂时无法整理，可以用固定回执交付原报告，标明肥鱼尚未复核。明确请求本人判断或创作时保留待办，自主成果沿用主动分享规则。 | 已完成的交付不依赖额外模型调用，同时保留原作者和判断归属。 |
| Q20 「先不研究」暂停该支线并保留成果。明确取消时，取消仅服务于该议题且未开始的任务，运行中的任务到安全位置停止。另有独立用途的委托继续。 | 让话题变化与任务生命周期对应，避免误取消独立工作。 |
| Q21 明确提供给当前话题的 QQ ZIP 可只读列清单、按需读其中的文本。需要落地时解到独立任务目录，保留原件。长期归档或覆盖已有资料先确认。 | 让研究材料可用，同时保留原件与授权范围。 |

## 实施顺序与验收

| 顺序 | 改动与完成判据 |
| --- | --- |
| 1. 组会恢复与闲聊 | 复用现有会议及 DSH 请求记录，补收已确认回复，并允许其他成员继续。以「一人正常、一人迟到、一人流中断」复现故障，迟到回复只收一次。验证闲聊可看到及时到达的新发言、研究型会议可保留独立初判，以及末轮插话和散会后补记的行为。 |
| 2. Go 调度与子任务 | 盘点并解除组会、公开任务、视频等路径中缺乏依据的固定并发值，按会话和实际资源处理冲突。让具名伙伴也能复用无名工具执行路径，保留父任务、发起角色、来源和回执。验同时间多个独立任务、真实资源排队、共享文件副本、Go 恢复、发起会话回传、暂停和取消传播。创作的角色分工写入既有指导；明确指定的主笔按验收样例核对。 |
| 3. 人民币预留与结果交付 | 先验证官方请求的有依据预留上界，再修低余额短请求和说明。覆盖工具定义、图文、并发和缺用量回执。验证肥鱼额度耗尽时，主人明确委托仍可一次交付 Go 原报告；要求肥鱼本人判断或创作时保留待办。 |
| 4. QQ ZIP 取材 | 复用共享收件箱和既有授权入口。用只读清单、选择性查看、按需解包核对原件与独立任务目录，验证解包不会写出任务目录或覆盖已存在资料。 |

顺序用于组织核查和施工。其它待验事项继续按维护手册排期。

## 工程待核

- 对照现有失败记录，在离线测试中独立复现晚到发言、流式请求缺少结束标记、末轮插话和掉线恢复，检查不同回执顺序只归档一次。对同一 DSH 的旧日常聊天卡住与组会中断分别追踪，不凭时间相近认定同源。
- 清点固定并发值和真正需要串行的范围，按实际请求、会话、设备和文件冲突验证。组会规则、Windows 的实际容量和 Go 的供应商限制各自取证。
- 证明官方 Flash 网关可用的安全预留上界，尤其是工具定义、图片和消息格式的计费输入。用模拟上游验证短请求低余额能通过，以及并发和缺用量回执时仍守住账本。
- 网页正文证据、媒体工作进程恢复、跨日项目和双机设置同步的现场缺口，留在[维护手册](FISHHOME_HANDBOOK.md)按功能补验。
